# Assess for Success website

The new website for Assess for Success (Topeka, KS): Behavioral Health Care for adults and youth, and A4S Sports for youth.
It's a static [Astro](https://astro.build) site, meant to be hosted on Netlify.

## Content rules (read this first)

- Content may only come from four sources: the client conversation, the whiteboard, the contact details from the old site, and answers the client has confirmed.
  Never add services, credentials, insurance information, prices, ages, schedules or session lengths that the client hasn't confirmed.
- Pricing is always "Call for pricing". What someone pays on their own can differ from what a court pays under a contract.
- Wrap anything unconfirmed in `<Confirm note="…">` (`src/components/Confirm.astro`).
  - Preview builds show it as a yellow chip.
  - `npm run build:prod` fails while any remain.
- The open questions are listed in [`docs/client-checklist.md`](docs/client-checklist.md). `npm run check:confirm` prints what is still on the site.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Local dev server at http://localhost:4321 |
| `npm run build` | Build to `dist/` (placeholders allowed, used for Netlify previews) |
| `npm run build:prod` | Build, then fail if any unconfirmed detail remains (used for production) |
| `npm run check` | Type-check Astro and TypeScript files |
| `npm run test` | Playwright: smoke tests, axe accessibility scans, 320px reflow, menu and form behavior (build first) |
| `SHOTS=1 npx playwright test screens` | Full-page screenshots of every page at 375, 768 and 1440 px in `test-results/shots/` |
| `npm run brand` | Regenerate logo SVGs, favicons and social share images from `design/` |

The tests use the installed Google Chrome (`channel: 'chrome'`), so no browser download is needed.

> **Node and Astro versions:** Astro is pinned to **7.4.1** because this machine runs Node 22.22.1, and Astro 7.4.2+ requires Node ≥ 22.23.4.
> Later patches fix two advisories. Neither affects this static site: one involves dynamic tag names built from user input, and the other is the `@astrojs/node` SSR adapter.
> Before launch, upgrade Node and run `npm install astro@latest`. Netlify builds with Node 22 (`netlify.toml`).

## Forms

Three Netlify Forms: `contact`, `referral-inquiry` and `sports-registration`. All three use a honeypot field instead of a CAPTCHA, and successful submissions land on `/thank-you/`.
The forms intentionally don't ask for health details, case numbers or children's birth dates, because Netlify Forms isn't meant for protected health information.
After the first deploy, open **Netlify → Forms → Form notifications** and set the notification email to `emailus@a4stopeka.com`.

## Logo

The old site only had a 108×60 px logo, so the logo was rebuilt from two sources:
- the monogram comes from the old site's vector trace (`design/legacy-site-assets/safari-pinned-tab.svg`)
- the wordmark is set in Roboto Condensed, the closest match by pixel comparison

It's a faithful stand-in. **Ask the client (or Rapid Rabbit Software, who built the old site) for the original vector file.** If you get it, replace the files in `src/assets/brand/` and update `scripts/build-brand.mjs`.

## Deploying

1. Push the repo to GitHub or GitLab and create a Netlify site from it. Production runs `npm run build:prod`, and deploy previews run `npm run build`.
2. Share a deploy preview with the client and collect the answers from the checklist. Replace every `<Confirm>`.
3. When `npm run build:prod` passes, add `a4stopeka.com` and `www` in Netlify.
   At the DNS host, change **only** the apex and `www` records, and keep the MX, SPF, DKIM and DMARC records so email keeps working.
   Lower the TTL a day ahead. Netlify provisions HTTPS automatically, which fixes the old site's certificate that expired in Oct 2024.
4. Remove the custom domain from the old GitLab Pages project. Submit `https://a4stopeka.com/sitemap-index.xml` in Google Search Console, and update the Google Business Profile hours and description.
